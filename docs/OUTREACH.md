# Small, consent-based pilot plan

1. Pick three genuinely relevant small CLI projects with documented Windows/Linux support, ideally from tools you already use. Read their contributing policy first.
2. Try their documented quickstart in your own disposable environment. If no problem exists, don't invent one.
3. Open an issue/discussion only where it is welcome. Describe the exact reproduction and offer an optional minimal CI check; do not mass-open promotional PRs.
4. With maintainer agreement, provide one marked block and a minimal config. Keep permissions read-only and introduce no secrets or mandatory AI accounts.
5. Ask whether the failure report was actionable and whether the project wants to retain it. Record consented public feedback and fix product bugs.

Draft message: “I tested the documented quickstart on [actual OS/version] and reproduced [specific result, link]. I maintain an open-source opt-in README check tool. Would a small CI regression check for this case be useful? No service account or API key is needed. I can send a focused patch after your approval.”

Do not send this template with unfilled placeholders. Do not claim an install or issue as adoption until the maintainer actually keeps it.
